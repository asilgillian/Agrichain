# Compact Loan Module Specification (Replit / Developer Ready)

## Module: Loan Management & Recovery

### Purpose

Manage seasonal agricultural loans linked to commodities, with:

* configurable loan products
* automatic deduction-at-source
* seasonal maturity handling
* restructuring
* penalties
* write-offs
* blacklisting
* approval workflows

---

# 1. Core Concepts

## 1.1 Loan Categories

Examples:

* Input Loans
* Cash Advances
* Emergency Loans
* Group Loans
* Staff Advances

---

## 1.2 Loan Products

Products belong to a category.

Example:
Category = Input Loans
Products:

* NPK Fertiliser
* Urea Fertiliser
* Coffee Seedlings

Products may have different prices but share:

* interest rate
* penalty rules
* maturity rules
* recovery logic

# 3. Loan Lifecycle

---

## ACTIVE SEASON

If:

* loan partially repaid
* season still active

Then:

* loan remains OPEN
* no penalties
* deduction-at-source continues

Loan statuses:

```plaintext
ACTIVE
RECOVERING
PARTIALLY_REPAID
```

---

## SEASON CLOSED

If season ends and balance exists:

### Step 1 — Grace Period

* no penalties
* recovery still allowed

### Step 2 — Penalty Period

* penalties applied automatically

### Step 3 — Restructure Eligible

* finance may restructure

### Step 4 — Non Performing

* loan marked overdue

### Step 5 — Frozen / Blacklisted

* new loans blocked

---

# 4. Auto Deduction Logic

When commodity payment is generated:

```plaintext
payment_amount
- active_loan_deductions
= farmer_net_payment
```

System:

1. retrieves active loans
2. checks deduction rules
3. applies repayment
4. updates balances
5. records repayment history

---

# 5. Farmer Controlled Repayment

At commodity delivery farmer may choose:

* repayment amount
* repayment percentage
* loan priority

Example:

```plaintext
Farmer Payment = 500,000
Farmer Chooses Repayment = 100,000
```

---

# 6. Finance Override

Finance may override farmer repayment choice.

Example reasons:

* season ending
* overdue loan
* high risk
* forced recovery campaign

Finance can:

* increase repayment
* recover full amount
* prioritise penalties first

All overrides require:

```plaintext
reason
user
timestamp
audit log
```

---

# 7. Deduction Priority Engine

Recommended order:

```plaintext
1. penalties
2. accrued interest
3. overdue loans
4. active loans
5. group liabilities
```

Configurable per organisation.

# 9. Approval Workflow

Threshold-based approvals.

Example:

```plaintext
< 200k        = Loan Officer
200k–1M       = + Finance
1M–5M         = + Manager
> 5M          = + Executive
```

Rules:

* maker-checker enforced
* submitter cannot approve own request

Applies to:

* loan approvals
* restructures
* write-offs

---

# 10. Write-Off Logic

Supported:

```plaintext
partial_principal
full_principal
interest_only
penalty_waiver
```

Requirements:

* multi-level approval
* mandatory reason
* audit trail

Written-off loans remain visible historically.

---

# 11. Blacklisting Rules

Triggered when:

* overdue exceeds threshold
* restructure limit exceeded
* fraud detected
* finance manually freezes

Effects:

* no new loans
* optional commodity purchase restrictions
* finance alerts

---

# 12. Inventory Integration (Input Loans)

For in-kind loans:

Example:

```plaintext
20 bags fertiliser issued
```

System:

1. deducts inventory
2. creates loan
3. links inventory transaction to loan

# 14. Critical Business Rules

```plaintext
- season active = no penalties
- partial repayment allowed
- deductions happen automatically during farmer payment
- finance override allowed with audit trail
- all approvals use maker-checker
- frozen/blacklisted farmers cannot receive new loans
- write-offs require multiple approvers
- all loan events are auditable
```
